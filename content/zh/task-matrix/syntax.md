任务就是标准 Markdown 复选框，插件在其上叠加表情标记与行内字段。所有写法都可以混用：

```markdown
## 发布
### 设计
- [ ] 线框图 🛫 2026-09-20 📅 2026-09-30 🆔 design 🔺
- [ ] 文案评审 📅 2026-09-26 ⛔ design
- [x] 启动会 🚩 2026-09-18
```

## 标记总表

| 写法 | 含义 |
|--------|---------|
| `- [ ]` | 打开的任务 |
| `- [x]` | 已完成（设置里可改） |
| `- [-]` | 已取消（设置里可改） |
| `🔺` | 关键（critical） |
| `⏫` | 最高优先级 |
| `🔼` | 高优先级 |
| `🔽` | 低优先级 |
| `⏬` | 最低优先级 |
| `📅 YYYY-MM-DD` | 截止日期 |
| `🛫 YYYY-MM-DD` | 开始日期 |
| `⏳ YYYY-MM-DD` | 计划日期 |
| `➕ YYYY-MM-DD` | 创建日期 |
| `🆔 task-id` | 任务 ID |
| `⛔ task-id` | 依赖某任务 |
| `✅ YYYY-MM-DD` | 完成日期（开「记录完成日期」时自动补写） |
| `🚩` / `#milestone` | 里程碑（甘特图渲染为菱形） |
| `[start:: …]` `[due:: …]` `[id:: …]` `[dependsOn:: …]` | Dataview 风格行内字段，与对应表情标记等价 |

`- [/]` 不是独立状态：任务一旦有过去的开始日期或 `#doing` / `#active` / `#next` 标签，就算进行中。

## 依赖

- `⛔ task-id` 声明依赖；依赖未完成时任务卡左边框标红；
- 编辑任务的「依赖」字段是一个下拉列表：列出所有带 ID 且未完成的任务，按截止日期就近排序——不用背 ID 也能连线；
- GTD 分类里，带依赖或 `#waiting` 的任务进「等待」列。

## 拖拽写入什么

拖拽与快捷按钮写入的内容完全一致，且固定不变（设置页里也是这么写的）：

**GTD 容器**

- → 进行中：加 `#doing` 和今天的 `🛫` 开始日期；
- → 等待：加 `#waiting`；
- → 完成：写入完成标记；
- → 收件箱：清掉流程标签。

**四象限容器**

- → Q1：高优先级 + 截止日改为今天；
- → Q2：高优先级，清掉会把它变紧急的截止日；
- → Q3：低优先级 + 截止日改为今天；
- → Q4：最低优先级，清掉截止日。

（象限里「重要」一侧的写入范围有硬约束：Q1/Q2 只能写高及以上，Q3/Q4 只能写中及以下或不写——任何选择都不会把任务推到另一半去。紧急没有专属标记，靠截止日期表达。）

如果写入后开始日期会晚于截止日期，会弹窗问你：把截止日挪到今天，还是两个都保留并给任务打上 `#due-date-conflict` 标记。
